# Getting started

## First launch

The first time PitCrew opens, a short welcome walks you through the two things it needs before your
first session: **downloading the voice model** (about 310 MB, once) and **setting up your audio**. The
download starts from the welcome itself and shows its progress; if it fails, try again or skip it —
nothing there is a dead end. The audio step then takes you to **Voice → Sound**, where you pick the
device the engineer plays on and hear a test call.

You can skip the welcome entirely. Everything it covers — and everything else you'd set on a first
run — lives on the **Voice** screen, and you can visit it whenever you like:

1. **Your name** — how the engineer addresses you on screen.
2. **A spoken language** — Brazilian Portuguese, English (US), Spanish, French or German. This is
   what you *hear*; the interface stays in English either way. See [voices and languages](voices.md).
3. **A voice** — download the speech model (~310 MB) and a voice pack. This is the one step that
   needs the internet; everything after it runs on your machine.

The header at the top of every screen tells you what's still missing, if anything is, and points you
at the Voice screen to fix it. Once your voice is set up, press **Regenerate them now** there to
pre-generate the lines PitCrew can prepare in advance — worth doing before your first race, so it
does not spend time synthesizing the spotter's callouts while you are trying to make a corner.

## Running it with iRacing

Start PitCrew and start iRacing, in either order. PitCrew watches for the sim and connects on its
own — the main window's header tells you whether it is connected, and to what session.

You do not need to restart PitCrew between sessions, or when you switch car or track. It notices.

Leave the main window wherever you like; you never need it during a race. If you want PitCrew to
launch with Windows, there is a setting for it.

## Companion and PIT on your network

Open **Cockpit dash** in PitCrew and turn on **Serve the dash on this network** when you want a
phone or another computer to follow the race. The code and address there work only on the same Wi-Fi
or Ethernet network as the rig.

The phone app finds and remembers the rig, then opens either **Dash Companion** or **Pit Strategy**.
You can also open the same pages directly in a browser at the rig's address:

```
http://<rig-address>:8422/companion/
http://<rig-address>:8422/pit/
```

Companion and PIT link to each other, reconnect when the rig returns, and keep their appearance and
layout in the browser or phone WebView you use. Turning the dash server off stops its network
announcement and makes both pages unavailable; it does not affect the engineer, overlay or sim
connection.

## The keys to remember

Three global shortcuts, which work while iRacing has focus:

| | |
|---|---|
| **Alt + H** | Show or hide the overlay |
| **Alt + R** | Say the last thing again |
| **Alt + M** | Mute or unmute the engineer |

**Alt + R** is the one you will actually use. Something gets said while you are busy being sideways
at the exit of a corner, and it is gone — that repeats it. **Alt + M** silences the engineer without
closing anything, for the laps where you want to be left alone.

## The overlay

A transparent, always-on-top window over the sim: proximity bars for cars alongside you, and a
radio-style area where the last message appears as text.

It is **click-through** — your mouse passes straight through it into iRacing, so it cannot steal a
click. It also keeps working with iRacing in exclusive fullscreen.

To move it, switch the overlay into edit mode from the main window; then it accepts the mouse and
you can drag it where you want. Its position is remembered per install, not per session.

The overlay is a **convenience, not the product**. Everything that matters is spoken, because the
whole point is that you should not be reading anything at 200 km/h.

## What PitCrew tells you

- **The spotter** — a car alongside, on which side, and when you are clear again.
- **Fuel** — how much you are using per lap, whether it gets you to the end, and warnings as the
  tank runs down.
- **Gaps and position** — who is closing on you, who you are catching, and where you sit in the
  field. Multiclass races are filtered by class, so a leader from another class does not get
  reported as if it were your race, and a car that is a lap ahead or a lap behind is named as
  exactly that, so you do not defend against somebody who is not racing you.
- **Your laps** — lap times, and a personal best when you set one.
- **Session events** — flags, the roster, pit and penalty calls.
- **Memory** — PitCrew keeps a profile per car/track combination, so it knows your best known lap
  there and can tell you how the current one compares.

Every one of these lines comes from a **phrase catalog** shipped as a JSON file. Nothing is
generated by a language model at race time, which is why it is fast, why it says the same thing in
the same situation, and why it never invents a number.

## Tuning what it says and when

Two things are adjustable, and they are separate on purpose:

- **Which voice speaks which category** — set per category in the app's settings.
- **When a call fires** — the spotter's debounce, fuel warning thresholds, the gap window, how long
  it stays quiet at the start of a session. These live in an optional file:

  ```
  %APPDATA%\race-engineer\tuning.json
  ```

  It **does not exist by default**, and no file means the built-in defaults. Create it only if you
  want to override something, and include only the keys you are changing.

  A worked example: the spotter's default is that a car has to be alongside for 150 ms before it is
  called, and gone for 400 ms before you hear "clear".

  ```json
  {
    "spotter": {
      "debounceCarMs": 150,
      "debounceClearMs": 400
    },
    "fuel": {
      "warningLaps": [5, 3, 1]
    }
  }
  ```

  If you get this file wrong, PitCrew falls back to the defaults rather than refusing to start.
